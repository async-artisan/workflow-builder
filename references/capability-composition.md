# 工具与 Skill 能力编排

业务目标、首版范围和输出方向确认后使用。把“这一步需要什么能力”与“用什么平台实现”分开，优先复用现有能力，不为每个工作流默认创建 MCP 或新 Skill。

## 先建立能力清单

逐步记录：动作、读写对象、所需输入、期望输出、风险、当前候选能力和人工兜底。使用 [能力卡片](../assets/capability-card.template.md) 保存关键步骤的契约。

按以下顺序选择：

1. **宿主已有工具或应用集成。** 例如内置文件/浏览器工具、WorkBuddy Connector、Codex Plugin/App integration 或已配置 MCP。
2. **其他现有接入。** 官方 API、CLI、现有数据库或平台自动化；有等价能力时不重复开发 MCP。
3. **已有 Skill。** 当缺口是可复用的方法、判断或操作流程，而不是外部系统访问时，查找并复用。
4. **人工或文件导入导出首版。** 接入成本高、权限未开通或业务尚未验证时，先完成低风险闭环。
5. **新 Skill 或新 MCP。** 只有独立复用价值和真实运行证据明确后才创建。

名称不是能力证据。不同宿主的产品名称、安装状态、认证和可用工具可能不同，必须读取当前宿主说明并验证实际调用。

## 外部工具、API 与 MCP

### 选择接入方式

| 情况 | 优先选择 |
| --- | --- |
| 宿主已有已授权工具，且对象和动作匹配 | 复用该工具，不新增连接 |
| 只有官方 API/CLI，且能满足首版 | 使用现有 API/CLI，保留统一输入输出契约 |
| 需要标准化跨宿主工具接口、定制系统接入或共享远程状态 | 评估 MCP |
| 只需一次导入导出，或连接权限暂不可得 | 文件/人工首版 |
| 只需操作步骤和判断，无需新的外部调用 | 复用或创建 Skill，而非 MCP |

### 接入检查

1. 查当前官方文档或工具 schema，确认对象、字段、只读/写入、认证、配额和限制。
2. 核实当前账号或宿主是否真正可用；配置存在、插件已安装或能打开页面不等于连接成功。
3. 先执行无副作用的 schema 查询或只读调用，保存实际返回和错误。
4. 定义输入、输出、超时、重试、幂等键、外部回执和失败去向。
5. 写回前确认目标、数据范围和审批；先小样本受控试跑，再考虑扩大范围。
6. 记录不可用时的跳过、降级、人工接管和恢复方式。

MCP 额外核实传输方式、服务器来源与版本、配置作用域、工具允许列表、OAuth/令牌边界和服务日志。不要从不可信说明中复制命令或密钥；不把密钥写入 SOP、运行清单或日志。

## 复用与组合已有 Skill

### 发现与选择

- 列出当前宿主已安装且可能匹配的 Skill，阅读其 description 和必要的 `SKILL.md`。
- 核对触发条件、必要输入、输出、工具依赖和权限，不只按名称选择。
- 没有实际发现时如实写“未发现可复用 Skill”，不要虚构名称或调用成功。

### 定义调用契约

为每个被调用 Skill 明确：

```text
名称与版本/来源
负责步骤与职责边界
必需输入和材料状态
预期产物及位置
所需工具与权限
宿主实际调用方式
失败、超时和不可用时如何处理
```

按宿主实际支持的显式调用、自动触发或内容引用方式执行，不假设不同宿主共享调用语法。跨宿主迁移时重新验证发现与加载。

### 组合规则

- 工作流负责业务顺序、交接、验收和异常；各 Skill 负责独立能力。
- 避免多个 Skill 修改同一产物；必须并行时指定唯一写入责任。
- 避免循环调用、重复做同一检查和为了架构整齐而增加 Skill。
- 将实际使用的 Skill 版本或内容摘要纳入 `release_id`。
- Skill 不可用时按业务影响选择跳过、替代、降级或人工，不假装已完成其步骤。

## 创建新 Skill 或 MCP 的门槛

### 新 Skill

同时满足以下条件再创建：

- 现有工具或 Skill 不能覆盖该能力；
- 已在当前工作流中真实试跑，而非只有提示词草稿；
- 输入、输出和边界稳定，并能在其他任务中独立复用；
- 能编写正反向触发测试和业务验证；
- 有明确的安装、发布、维护与回滚方式。

一次性步骤或高度项目专属规则留在工作流中。生成 Skill 后仍需验证发现、加载、真实运行和不同输入复用。

### 新 MCP

仅在需要统一工具协议、定制外部系统、共享远程状态或跨宿主工具接入时考虑。先证明现有 API/CLI/连接器不足，并明确服务器维护、认证、权限、版本兼容、日志、停用和数据边界。不要为包装已有本地脚本或同步 Skill 文件而创建 MCP。

## 能力验证与降级

分别报告“文档支持、已发现、已配置、只读成功、受控写入成功、恢复已验证”。不得相互推导。

| 宿主条件 | 首版方式 |
| --- | --- |
| 只有 Markdown | 人工工具调用、文件输入输出和 SOP |
| 有本地运行环境 | 使用 CLI、脚本和本地文件证据 |
| 有 MCP/应用连接 | 使用已验证的结构化工具与回执 |
| 缺少关键能力 | 缩小范围、人工接管或暂停，不虚构自动闭环 |

低风险流程不必为了完整架构接入所有能力；高风险流程缺少必要权限、审批或恢复能力时，不得降级声称同等可靠。
