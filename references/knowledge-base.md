# 工作流中的知识库方法

当任务需要长期查资料、跨材料整理、沿用业务规则或追踪版本时使用。先说明知识用途、资料范围、使用者和可访问范围，选择一小组可信材料验证；不为无关任务强加检索系统。

## 组织、入库与更新

| 层 | 职责 |
| --- | --- |
| 原文，如`raw/` | 保留可靠证据、来源和版本，不改写事实、不覆盖旧原件 |
| 主题知识，如`wiki/` | 基于原文形成主题页、索引和更新日志，结论回链原文 |
| 项目规则 | 说明入库、查询、引用、冲突与更新处理方式 |
| 检索索引 | 由实际检索工具维护，可重建；不代替原文 |

命名与元数据至少能辨识日期、来源、主题和版本；已有原件名称保持稳定，可用元数据补充，不强制重命名。记录来源位置、生效/发布日期、版本和状态，如draft、current、superseded；未知就标明，多个版本冲突时并列呈现，交由负责人决定当前口径。

长文按标题、完整主题或表格边界切分，保留条件、例外、否定和完整表格行。每段保留文件、标题路径、版本与页/行位置。切分方式根据实际材料验证，不照搬固定长度。

主题页中的总结、关系和结论都应回链到支持它的原文。先用实际可用的原文验证来源与主题整理；涉及多份材料时再验证跨文件整理，单一来源时标记为不适用，不为验证凑材料。

更新时保留旧原文，明确新旧状态，刷新主题页与索引。当前查询应排除已被替代的版本；需要历史追溯时明确使用历史模式和版本，不能混入当前答案。是否被替代须有依据，不能仅凭文件日期自行裁决。

## 检索和回答

同时覆盖主题知识与原文：先找候选，再回读原文核实上下文、条件和版本。使用者应能沿引用找到原始位置。

按实际工具确认各项能力：

- 关键词检索：查精确名词和条件。
- 语义召回：查相近意思的段落。
- 查询扩展：用不同表述增加候选覆盖。
- 重排：比较候选与问题的相关性。
- 最终回答：根据已经核实的证据组织结论。

这些能力可由不同工具或模型承担，模型配置与切分参数依实际任务和版本决定。记录索引覆盖、配置、实际查询结果；下载了模型、写了配置或能打开文件，都不能证明对应检索能力已经可用。更换向量模型后重新生成向量，避免新旧向量不兼容。

没有检索工具时可先用主题索引定位并人工回读，明确记录“文件查询/知识整理可用，独立检索能力未接通”。关键词检索结果不能冒充语义检索。云端接入先明确上传范围、访问者与同步方式。

回答给结论、原文文件、标题和页/行位置，必要时附支持结论的原文。没有依据、无法读取或版本冲突时如实说明，检索未命中不能推出资料必然不存在。

## 验证质量与更新效果

按本次承诺的能力和风险选择测试，用实际知识库执行以下适用问题，保留结论、命中文件/位置和支持原文；只交付组织方案而未建库时，明确“检索未运行”：

| 问题 | 验证目标 |
| --- | --- |
| 精确术语或条件 | 找到明文证据 |
| 同义口语改写 | 同一问题换问法仍能找到依据 |
| 跨文件问题（仅多源范围） | 结合相关材料且分别有引用；单一来源时不适用 |
| 范围外问题 | 明确没有答案，避免猜测 |

需要验证更新机制时，使用明确可更新的低风险材料或测试副本，用同一个问题复测：新版结论应生效、旧版退出当前结果，历史原件仍可追溯；不得为测试擅自改写业务原件。只验证初次检索不能证明更新机制有效，未做更新测试时标为“更新未验证”。

交付时报告实际读取、切分、索引过的文件及版本、主题页与来源、检索和更新的真实结果、未接通能力和待人工核实项。完整维护与检索各自有证据后，才能说明对应能力已验证。
