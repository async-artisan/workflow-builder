# 工作流效果评测

需要把“已试跑”升级为“已复用验证”、比较版本或准备上线时使用。评测证明的是特定版本、输入范围和风险边界内的效果，不证明所有场景永远可靠。评估模糊需求访谈和引导质量时，使用 [需求引导对话评测](../evals/dialogue-rubric.md)。

## 先冻结评测计划

运行前记录：

- 候选 `release_id`、业务目标和允许范围。
- 人工流程或上一版本的基线：质量、耗时、人工返工、模型/工具成本和失败影响。
- 正常、边界、无效输入和关键异常用例；区分调参样本与最终未见样本。
- 每个用例的 oracle：可自动执行的业务断言，或明确的人工评分 rubric。
- 通过阈值、重复次数、关键安全用例和预算停止条件。

不要给所有任务固定相同样本数。根据业务风险、输入变化和希望控制的失败率说明样本依据；随机性流程应重复运行并报告失败情况，而不是只保留最好一次。

## 用例与判定

`evals/cases/` 中的用例至少包含：

| 字段 | 用途 |
| --- | --- |
| `case_id` 与 `type` | 唯一标识及 normal / boundary / invalid / fault |
| `input` | 输入位置、来源、版本和是否为合成材料 |
| `assertions` | 可观察的业务结果、关键条件和证据要求 |
| `baseline` | 人工或旧流程的比较依据 |
| `threshold` | 通过条件和最低样本/重复要求 |
| `critical` | 失败时是否阻断复用或发布 |

文件存在、命令退出码为 0、格式正确和模型自评分不能单独充当业务 oracle。人工评分必须保留评分人、原话或评分记录及依据。

## 结果与成本

每次运行关联 `release_id` 和 `case_id`，保存输入摘要、产物、逐项断言、异常、人工接管和实际成本。至少比较：

- 业务断言通过率与关键用例失败数；
- 人工驳回、修改和接管比例；
- 从启动到验收的总耗时；
- 单位验收成本。

```text
单位验收成本 =
模型与工具成本 + 人工成本 + 重试与返工成本
------------------------------------------------
最终达到验收标准的业务结果数
```

关键安全用例失败不能被平均分抵消。未达到预先冻结的阈值时，不得声称“已复用验证”或扩大自动化范围。

## 复用与变更

- “已复用验证”至少要求使用未参与调参的不同输入，按同一 SOP 达到冻结阈值，且无未解决的关键失败。
- 修改步骤、模型、工具、权限、适配器或知识版本后，只重跑受影响用例及其必要回归，并绑定新的 `release_id`。
- 上线候选先进行小范围 canary；未达到阈值时不得自动转为 active。质量或安全停止条件触发后，停止接收新运行并保留在途对账与人工接管入口。
- 保存负面结果和未覆盖范围。合成示例可验证评测机制，但不能冒充真实业务效果证据。
