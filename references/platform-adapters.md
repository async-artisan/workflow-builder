# 平台选择矩阵与适配规范

仅在需要选择运行平台、连接外部系统或迁移工作流时使用。先选择能承载业务闭环的最简单平台，再核实当前账号、版本和工具实际支持的能力；不要根据平台名气或功能列表决定架构。

## 选择顺序

1. 确认系统记录所在位置：任务、文档、数据、审批和结果主要留在哪里。
2. 确认触发方式：人工启动、定时、事件、消息或Webhook。
3. 确认执行边界：只读分析、生成草稿、写回业务系统，还是发布/审批等高风险动作。
4. 确认运行要求：权限身份、人工门禁、日志、重试、幂等、版本、成本和维护人。
5. 优先复用当前平台和已有连接；只有关键需求无法满足时才增加新平台。

## 平台选择矩阵

| 当前工作重心 | 优先候选 | 适配重点 | 不适用或需换路的信号 |
| --- | --- | --- | --- |
| GitHub Issues、Projects、Discussions、仓库文档 | GitHub 原生能力、GitHub Agentic Workflows 或现有仓库自动化 | 仓库权限、Actions/引擎、令牌范围、项目读写、PR/人工审批、运行日志 | 业务记录不在GitHub；组织禁用相关能力；无法安全授予写权限 |
| 团队聊天、邮件、日历和在线文档 | 当前办公套件的Agent/自动化能力，或已有iPaaS连接 | 版本与许可、触发器、连接器、执行身份、消息/文档写回、审批和配额 | 所需版本未开通；只能读不能写；无法明确机器人或执行人身份 |
| Jira、Linear、CRM、客服等业务系统 | 业务系统原生Agent/自动化，或官方API与现有集成 | 对象模型、状态迁移、Webhook、字段权限、审计记录、失败补偿 | 连接只能覆盖部分对象；自动写回会破坏现有状态机或审批规则 |
| 跨系统、多步骤、需要明确重试和状态管理 | n8n、Power Automate、现有iPaaS或定制编排运行时 | 凭据隔离、状态保存、幂等键、重试策略、死信/人工恢复、可观测性 | 只是简单单系统任务；引入编排平台的维护成本高于收益 |
| 需要自有Agent、特殊模型或私有部署 | Agent SDK/API、MCP与定制服务 | 工具白名单、模型与数据边界、会话状态、人工接口、评测和发布回滚 | 无长期维护人；现有SOP加人工执行已能满足目标 |
| 暂无合适平台、权限未开通或仅需低风险首版 | 文件/对话中的SOP、模板与人工执行 | 输入输出位置、人工步骤、运行记录、后续自动化边界 | 把草稿误当自动化；手动步骤没有负责人或无法持续维护 |

平台名称只用于定位候选，不代表当前环境已安装、已连接或支持所需功能。涉及具体产品能力、许可或配额时查阅当前官方资料并记录核实日期；无法核实时保留未知。

## 可插拔平台适配器契约

为每个实际选中的平台写一份简短适配说明。字段可按需合并，但不得省略已发现的限制：

```text
适配器：平台与版本/环境
适用场景：为什么由该平台承载
系统记录：权威数据和业务结果保存在哪里
触发：人工/定时/事件；实际配置位置
输入映射：SOP参数、材料和平台字段的对应关系
动作映射：只读、草稿、写回、发布；各自动作所需权限
人工门禁：审批人、审批内容、批准后的下一步
运行与恢复：执行入口、日志、重试、幂等、取消和人工接管
产物与证据：结果、运行ID、检查证据和签核位置
限制：未接通能力、许可/配额、已知失败路径
验证状态：仅文档推导 / 草稿已生成 / 已试跑 / 已现场验证
维护：负责人、变更入口、需要重新验证的环节
```

适配器只负责平台映射，不复制业务SOP。业务目标、参数、步骤、验收和签核保持在可移植核心中；平台专属触发器、字段、连接和运行ID留在适配层。

## 落地与验证

1. **映射。** 从同一份SOP生成平台草稿，标出无法映射的参数、步骤和人工门禁。
2. **静态检查。** 校验配置格式、权限、引用、连接和危险动作；静态通过不等于可运行。
3. **受控试跑。** 默认使用测试对象、最小数据和非发布模式。真实写入前确认目标与影响，记录运行ID和实际结果。
4. **异常验证。** 按风险测试缺输入、无权限、重复触发、超时和部分失败；受控模拟不能冒充真实故障恢复证据。
5. **交接。** 保存平台适配说明、业务SOP、人工签核和回滚/停用入口。平台能力变化后重新验证相关映射。

“文档上支持”“配置已生成”“连接已成功”“真实试跑已通过”分别报告，不相互推导。
